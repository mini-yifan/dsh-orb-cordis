## 1. 产品定义

### 1.1 一句话

**一个账号，把一个人的所有设备连成一台「虚拟电脑」：在任意一台设备上，你都能看到并使用其他设备的工作区、会话和后台 Agent；悬浮球是统一入口，文件跟着任务走，服务可以完全跑在自己的服务器上。**

这句话有三个关键词：

- **一个账号**：一个人的信任域，不是团队、不是公开市场。
- **一台虚拟电脑**：不是把设备变成一台操作系统，而是把「工作区 + 会话 + Agent + 文件」连成一张网。
- **自己的服务器**：内置服务是我们自己的；用户也可以自建；不接第三方账号/中转。

### 1.2 产品由两部分组成

| 能力 | 名字 | 一句话 | 用户感知 |
|---|---|---|---|
| A | **在场（Orb On-Screen）** | 悬浮球看得见你面前的屏幕，也能动手 | 「它就在我手机上，知道我在看什么」 |
| B | **互联（Orb Mesh）** | 一个账号把多台设备的工作区、会话、Agent、文件连起来 | 「我所有的电脑和手机像一台电脑」 |

两者合起来才是完整产品：

- 只有 A：是一个手机/桌面的 Computer Use 助手，设备之间还是孤岛。
- 只有 B：是一个多设备工作区浏览器，悬浮球没有「在场感」。
- A + B：悬浮球既能处理眼前的屏幕，也能把任务派到别的设备；用户在任意设备上都能看到全局。

### 1.3 六条产品公理

如果这六条不成立，后面的功能都会走样。

1. **一个账号 = 一个私人设备网络。**
   账号只属于一个人/一个信任域。设备登录后自动成为网络节点；不接第三方账号、不接第三方中转。内置服务是我们自己的，用户也可以自建。

2. **每台设备都是完整节点，不是瘦客户端。**
   每台设备有自己的 DSH、工作区、文件、应用、Agent。Mesh 只是让它们互相可见、可调用；执行仍然发生在设备本地，不集中到云。

3. **一棵统一的工作区树。**
   本机工作区在上面；下面是同账号的其他设备：设备 → 工作区 → 会话。树是实时的，能看到在线/离线、正在跑、等你确认。远程会话可以打开、看、输入、暂停。

4. **一个悬浮球，任意设备上的统一入口。**
   悬浮球既能做本机 Computer Use，也能把任务派给其他设备的后台 Agent。用户不需要记住「这个任务该在哪台机器上做」，只需要说想要什么。

5. **任务是会话，文件是附件。**
   跨设备工作以「任务/会话」为单位；文件跟着任务走，不做全量同步盘。远程会话对用户可见、可干预，不是黑盒。

6. **用户主权 + 自建服务。**
   用户能看到、暂停、插话；只能改自己设备的名字；设备可撤销；服务可以跑用户自己的服务器。内置服务也是我们自己的，不依赖第三方。

### 1.4 这个产品是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 个人多设备 DSH 网络 | 远程桌面 / 屏幕串流 |
| 统一工作区树 + 远程会话 | 云盘 / 全量文件同步 |
| 跨设备 Agent 调度 | 团队协作 / 共享账号 / RBAC |
| 任务级文件流转 | 云 IDE / 在线 Office |
| 自建 + 内置的互联服务 | VPN / 内网穿透工具 |
| 悬浮球的「多设备大脑」 | 替代 DSH / 替代操作系统 |
| 一个人/一个信任域 | 跨账号联邦 / 公开设备市场 |

一句话：**它把「多台设备」变成「一套工作区 + 一个助手 + 一张任务网」，但不是把多台设备变成一台操作系统。**

## 2. 背景与问题

### 2.1 现状

- 每台设备各跑一份 DSH：工作区、会话、文件、Agent 都在本机。
- 设备之间靠人肉搬运：AirDrop、微信传文件、远程桌面、SSH、云盘。
- 远程访问工具大多解决「连上另一台机器」，不解决「把多台机器当成一套工作区」。
- 第三方远程/账号服务让用户在隐私和控制上不放心。

### 2.2 用户的真实痛点

| 痛点 | 现在怎么做 | 想要什么 |
|---|---|---|
| 任务在另一台设备上 | 切换电脑 / 远程桌面 / 手动 SSH | 在当前设备说一句话，任务派过去 |
| 文件在另一台设备上 | AirDrop / 微信 / 云盘 / U 盘 | 文件作为任务附件自动来回 |
| 远程 Agent 在干什么 | 切过去看 / 不知道 | 当前设备的树里实时看见，可暂停、可插话 |
| 多台设备像多台电脑 | 记路径、记设备、记账号 | 一个账号、一棵树、一个悬浮球 |
| 不信任第三方 | 自建各种工具 | 互联服务自己部署，数据自己掌握 |

### 2.3 机会

DSH 已经提供了「工作区 / 会话 / Agent / 工具」这套本地模型；悬浮球已经提供了「Computer Use + 后台 Agent」这套执行模型。把它们用「账号 + 设备 + 统一树 + 任务附件」连起来，就是一个新的产品层：

> **不是再做一个远程控制，而是把一个人的所有 DSH 设备组织成一台「虚拟电脑」。**

## 3. 目标用户

### 3.1 主要用户

**一个人，2–5 台设备，已经在用 DSH / 悬浮球。**

- 典型组合：Mac + Windows + 手机（+ 平板）。
- 工作流跨设备：文档在 Windows、开发在 Mac、照片在手机。
- 愿意为「少切换、少搬运、看得见」付费或自建。
- 在意隐私和控制，不接受第三方账号/中转。

### 3.2 次要用户

- 自建/极客用户：愿意自己部署互联服务，要求数据在自己服务器。
- 小型工作室：几个人各自多设备（后续版本，v1 不做团队共享）。

### 3.3 非目标用户（v1）

- 需要团队协作、共享账号、RBAC 的团队。
- 只想远程桌面/串流，不需要 Agent 工作区的用户。
- 不用 DSH、不愿意装插件的普通用户。

## 4. 核心场景（JTBD）

### 4.1 在场：手机上的悬浮球

> 我在手机上看到一条消息 / 一张图 / 一个页面，长按悬浮球说「帮我处理这个」，松手就发；它已经看到了我面前的屏幕，直接开始操作。

- 用户不需要先截图、再上传、再描述。
- 用户不需要离开当前 App。
- 敏感操作仍然由用户确认。

### 4.2 跨设备改文档

> 我在 Mac 上对悬浮球说：「把 Windows 上 X 文档字体改蓝，把 Mac 上同名文档改红。」
> 悬浮球派两个后台 Agent；两个会话都出现在我 Mac 的树里；我能看实时进展，能暂停/插话；完成后它汇总。

### 4.3 手机照片进 Mac 文档

> 我在 Mac 上对悬浮球说：「把手机里这张照片插到 Mac 的 Y 文档。」
> 悬浮球让手机后台 Agent 找到照片并作为附件返回；Mac 端接收后完成插入。

### 4.4 在 A 看/管 B 的任务

> 我在 Mac 上看到 Windows 的后台 Agent 正在跑；点进去看实时消息；暂停；在输入框里给 Windows 的 Agent 新指令；悬浮球同时也在等这个任务的结果。

### 4.5 设备命名与身份

> 我把这台 Mac 改名为「书房 Mac」；我的手机、Windows、网页门户都看到「书房 Mac」；但手机和网页不能改它的名字，只有这台 Mac 自己能改。

### 4.6 自建服务

> 我不想把设备信息交给第三方；我在自己的服务器上部署互联服务，所有设备登录我自己的地址；功能和内置服务一致。

## 5. 核心概念与心智模型

### 5.1 概念

| 概念 | 定义 | 用户怎么理解 |
|---|---|---|
| **账号** | 一个人的信任域，拥有若干设备 | 「我的账号」 |
| **设备** | 一台登录了账号、运行 DSH + 悬浮球的机器 | 「我的 Mac / Windows / 手机」 |
| **工作区** | 设备上的一个项目/文件夹 | 「那个项目文件夹」 |
| **会话** | 一次正在发生的对话/任务 | 「那条正在跑的对话」 |
| **任务/派发** | 悬浮球把一段工作交给某台设备的后台 Agent | 「我让它去那台机器干活」 |
| **附件** | 跟着任务走的文件 | 「发给它的文件 / 它给我的文件」 |
| **审批** | 跨设备动手前的确认 | 「它问我要不要继续」 |
| **前台 Agent** | 悬浮球里的 Computer Use agent | 「悬浮球自己」 |
| **后台 Agent** | 某台设备上的标准 DSH 会话 | 「那台机器上的工人」 |

### 5.2 统一工作区树

```
本机
 └─ 工作区 A
      └─ 会话 1
      └─ 会话 2
 └─ 工作区 B
      └─ 会话 3

其他设备
 └─ Windows电脑
      └─ 工作区 X
           └─ 会话 a（实时）
           └─ 会话 b
      └─ 工作区 Y
           └─ 会话 c
 └─ 手机
      └─ 工作区 M
           └─ 会话 d
```

- 本机工作区在上；其他设备在下方，按设备分组。
- 设备 → 工作区 → 会话，三层。
- 每个会话显示状态：空闲、运行中、等待确认、失败、离线。
- 点远程会话 → 打开它，看实时消息，输入，暂停。
- 设备离线 → 显示离线态和上次在线时间；缓存可看，不可执行。

### 5.3 「把多台设备当成一台设备」的准确含义

**是：**

- 一个账号、一棵树、一个悬浮球；
- 任意设备的工作区/会话可浏览；
- 任意设备的后台 Agent 可被调用；
- 文件跟着任务走；
- 用户在任意设备上都能看到/干预。

**不是：**

- 不是一个操作系统、一个文件系统；
- 不是所有文件自动同步；
- 不是远程桌面/串流；
- 不是把应用搬到当前设备运行；
- 不是团队共享空间。

### 5.4 设备命名规则

- 默认名由系统分配：`Mac1`、`Mac2`、`Windows1`、`Phone1`、`Tablet1`……账号内唯一。
- **只有当前设备能改自己的名字**，入口在悬浮球插件的「互联」设置里。
- 其他设备、账号 Web 门户都只能读，不能改。
- 改名后，所有设备的工作区树和门户立即显示新名字。
- 名字是身份的一部分，不允许远程改名/冒充。

## 6. 产品原则

1. **先看见，再动手。** 远程任务的状态、进度、审批默认可见。
2. **不做黑盒。** 远程会话就是用户能打开的会话，不是悬浮球的私有后台。
3. **文件跟任务，不跟设备。** 避免变成同步盘；文件流动有任务上下文。
4. **只改自己的名字。** 身份清晰，防止远程改名/冒充。
5. **本地执行，云端只协调。** 服务不跑任务、不存内容。
6. **手机是特殊设备。** 远程操作手机要额外授权和确认。
7. **自建优先，内置是便利。** 不把用户锁在第三方服务里。
8. **可暂停、可解释、可撤销。** 任何跨设备动作都要有停止和撤销路径。

## 7. 功能需求

优先级：**P0 = v1 必须有；P1 = v1.1/后续；P2 = 远期。**

### 7.1 能力 A：悬浮球在场（Orb On-Screen）

#### FR-A1 长按说话，松手发送（P0）

- 长按悬浮球进入录音状态，显示波形/进度；
- 松手后转写并发送；上滑/滑出取消；
- 太短、静音、转写失败给提示，不发送空消息；
- 发送后可以继续用输入框补充。

**验收：** 用户不说话、只长按，不会误发；一次完整的「长按—说—松手」能在 3 秒内看到消息进入对话。

#### FR-A2 发送时附带当前屏幕截图（P0）

- 松手发送时，自动截取当前屏幕（不含悬浮球/面板）；
- 截图作为这一轮消息的图片附件，和语音转写文字一起发给 Agent；
- 安全页面/禁止截图时，只发文字，并明确告诉 Agent「当前屏不可截」；
- 截图前隐藏悬浮球；截图后恢复；
- 用户能感知「这次带了截图」，可取消/重发。

**验收：** Agent 在消息里同时看到截图和文字；截图中不出现悬浮球；银行/密码页不会泄露截图。

#### FR-A3 对当前屏做 Computer Use（P0）

- Agent 先看截图（用户说话时的屏幕），再对当前屏操作；
- 操作以「看得懂 + 点得准」为准：先观察，再点击/输入/滚动；
- 敏感操作（付款、密码、验证码、删除）交给用户确认；
- 用户可随时停止；停止后不继续动作；
- 不创建虚拟屏，不接管整台手机；用户和 Agent 共用同一块屏。

**验收：** 一个「在当前 App 里点按钮/填表单」的任务能完成；敏感步骤出现确认；停止后 Agent 不再动作。

#### FR-A4 本机后台 Agent（P0）

- 需要文件、命令、长任务的，交给本机标准模式后台 Agent；
- 后台会话出现在悬浮球对话/树里；
- 完成/失败/需要确认有通知；
- 用户可暂停/插话。

**验收：** 一个「查资料 + 写文件」的任务能由后台完成并回到悬浮球。

#### FR-A5 悬浮球面板（P0）

- 显示对话、工具状态、任务状态；
- 支持新建、历史、停止、在 App 打开；
- 语音/文字输入；
- 失败/离线有明确提示。

**验收：** 用户不打开主窗口也能完成一轮对话并看到结果。

#### FR-A6 不做虚拟屏（P0，产品边界）

- 不把手机变成虚拟屏；
- 不要求用户切走；
- Agent 操作时用户看得见，可随时接管；
- 这是产品承诺，不是实现细节。

**验收：** 用户能说清楚「刚才 Agent 动了哪里」，不需要理解虚拟屏。

### 7.2 能力 B：超级互联（Orb Mesh）

#### FR-B1 互联服务与账号（P0）

- 悬浮球插件设置里有「互联」模块；
- 支持两种服务：
  - **内置服务**：我们自己的服务器，用户点登录/注册；
  - **自建服务**：用户填自己的服务器地址，用同一套能力；
- 登录/注册在网页完成，回到插件后显示已登录；
- 账号只属于一个人/一个信任域；
- 不接第三方账号、不接第三方中转；
- 服务不存会话内容/文件明文。

**验收：** 用户能在内置或自建服务上完成注册/登录；两台设备登录同一账号后互相可见；断开服务后本地 DSH 不受影响。

#### FR-B2 设备注册、命名、在线状态（P0）

- 设备登录后自动注册，分配默认名；
- 显示平台、版本、在线/离线、上次在线；
- 当前设备可在「互联」设置里改名；
- 其他设备、Web 门户只能读名字；
- 改名实时同步到所有设备和门户；
- 支持撤销/移除设备（P1）；
- 退出登录后设备从账号消失/离线，本地数据不动。

**验收：** Mac 改名为「书房 Mac」后，手机/Windows/门户都显示新名字；手机和门户没有改名入口；撤销后该设备不能再被调用。

#### FR-B3 统一工作区树（P0）

- 本机工作区在上；
- 其他设备按设备分组，展开为工作区，再展开为会话；
- 实时状态：运行中、等待确认、空闲、失败、离线；
- 离线设备显示缓存和上次在线时间；
- 点击远程会话可打开；
- 支持刷新/重连；
- v1 可以先做「远程只读 + 悬浮球任务可交互」，v1.1 再做全部远程会话可交互。

**验收：** 用户能在 Mac 的树里看到 Windows 的工作区和会话；Windows 新建会话/开始运行，Mac 树里在数秒内出现状态变化；离线设备有明确标识。

#### FR-B4 远程会话（P0）

- 打开远程会话，实时看消息、工具调用、状态；
- 在输入框给远程 Agent 发新指令；
- 暂停/停止当前执行；
- 显示「正在哪台设备上执行」；
- 需要用户确认/回答时，在本地可见（v1 可以先提示去目标设备确认，v1.1 支持本地处理）；
- 支持附件上传/下载；
- 断线后自动重连，消息不丢。

**验收：** 用户能在 Mac 上看到 Windows 会话的实时输出；能发一条新指令；能暂停；暂停后 Agent 不再继续动作。

#### FR-B5 悬浮球跨设备调度（P0）

- 任意设备的悬浮球都能把任务派给同账号的其他设备；
- 任务默认交给目标设备的**标准模式后台 Agent**；
- 派发时带上：任务描述、必要上下文、附件；
- 任务会话出现在统一树里，用户可打开/暂停/插话；
- 悬浮球等待/读取结果，汇总给用户；
- 目标设备离线/忙/失败时，明确告知，不假装成功；
- 用户可指定设备，也可让悬浮球按设备名/平台选择；不确定时询问。

**验收：** Mac 悬浮球能把「改 Windows 文档」派给 Windows 并拿到结果；用户能在 Mac 树里看到该会话；能暂停/插话；结果回到 Mac 悬浮球。

#### FR-B6 文件与附件（P0）

- 本机文件可以作为附件随任务发给远程 Agent；
- 远程 Agent 的结果文件可以作为附件回到本机；
- 手机照片/文档可以作为附件参与任务；
- 文件与任务绑定，有明确的来源/去向/状态；
- 不做全量同步盘；不做自动镜像；
- 大文件有进度、失败重试、大小限制；
- 任务结束后文件保留/清理策略可配置（P1）。

**验收：** Mac 能把本地文件发给 Windows 任务；Windows 能把结果文件回传 Mac；Mac 能把手机照片取回并插入文档；用户能看出文件从哪来到哪去。

#### FR-B7 状态、通知与错误（P0）

- 远程任务：已派发、运行中、等待确认、完成、失败、取消；
- 设备：在线、离线、重连中；
- 本地通知/角标/树内状态；
- 任何失败都有可读原因和下一步；
- 不静默失败、不假装完成。

**验收：** 目标设备离线时，用户立即看到「Windows 离线」而不是一直转圈；远程任务失败时能看到原因。

#### FR-B8 安全、权限与控制（P0）

- 账号/设备身份认证；会话内容端到端加密；服务只做协调；
- 改名只允许当前设备；
- 设备可撤销、会话可断开；
- 跨设备动作有范围：可配置「允许哪些设备调用我」「允许文件/命令/手机操控到什么程度」；
- 敏感操作（付款、密码、验证码、删除）必须用户确认；
- 手机作为被控端要额外授权和明显提示；
- 审计日志（谁在什么时候调用了哪台设备、做了什么）P1；
- 一键停止/断开所有跨设备连接。

**验收：** 撤销设备后无法再调用；未授权设备看不到工作区；手机被远程操作时有明显提示；敏感操作必须确认。

**v0 裁剪（[19](19-v0-decisions.md) P4）：** v0 不提供「文件/命令到什么程度」的工具级范围配置。被派到某台设备的任务以该设备用户的身份运行 `bash` 并读写文件，等价于同账号的其他设备可以在本机以你的身份执行命令；这一条必须对用户讲清。手机屏幕操作仍默认关闭、有独立开关。唯一的刹车是「一键停止所有远程任务 + 退出互联」。

#### FR-B9 设置与 Web 门户（P0）

**悬浮球「互联」设置：**

- 登录/退出；
- 选择内置/自建服务，填服务器地址；
- 当前设备名（可改）；
- 当前设备在线状态；
- 已登录设备列表（只读）；
- 连接测试/错误提示；
- 安全设置（允许被调用、文件权限、手机被控）。

**Web 门户：**

- 注册/登录；
- 设备列表：名字、平台、在线、上次在线；
- 只读，不提供改名、不提供远程工作区、不提供会话内容；
- 可选：移除设备、退出登录（P1）。

**验收：** 用户能在门户看到设备但不能改名；能在插件里改当前设备名；能把服务切换到自建地址。

#### FR-B10 多端体验（P0/P1）

- 桌面 DSH、手机 dsh-Go 上都能进入「互联」；
- 核心概念一致：设备、工作区、会话、任务、附件；
- 桌面端的统一树/远程会话体验受产品路线影响（见 D3）：
  - 官方 DSH + 插件：先做侧栏设备面板 + 远程会话面板/切换；
  - 自研桌面壳：做完整统一树 + 主会话区；
- 手机端优先做完整统一树/远程会话（可改原生 App）；
- 键盘、语音、无障碍、中文/英文。

**验收：** 同一账号在桌面和手机上看到同一批设备/工作区/会话；核心操作一致；文案中英一致。

## 8. 非功能需求

### 8.1 隐私与安全

- 服务端不存会话明文、不存文件明文；端到端加密；
- 设备私钥只在设备本地；
- 账号被盗/设备丢失有撤销路径；
- 跨设备动作可审计、可停止；
- 手机被控有额外确认；
- 提示注入防护：远端内容/文件名/会话结果不作为指令执行，敏感动作仍需确认。**v0：只做 persona 与回传模板约束，不设验收；风险记录在 [16 §9](16-v0-plan.md)，决策见 [19](19-v0-decisions.md) P5。**

### 8.2 性能

| 项 | 目标 |
|---|---|
| 树首次加载（2–3 台设备） | ≤ 2 秒（局域网） |
| 远程会话消息延迟 | 与本地会话同量级（目标 ≤ 1 秒） |
| 任务派发到远程开始执行 | ≤ 5 秒（在线设备） |
| 文件传输 | 有进度；失败可重试；大文件不阻塞 UI |
| 设备离线检测 | ≤ 30 秒内可见 |

### 8.3 可靠性

- 断线重连；重连后树/会话状态恢复；
- 任务不重复派发；有任务 ID/状态；
- 目标设备离线/忙/失败有明确状态；
- 不静默丢消息、不假装完成；
- v1 不做离线队列（明确告知）。

### 8.4 兼容性

- DSH 桌面版 + dsh-Go；
- 同一账号下设备版本不一致时，降级/提示；
- 内置服务与自建服务同一套能力；
- 中英文界面。

### 8.5 可运维性

- 内置服务可观测、可升级、可备份；
- 自建服务有一键部署/升级文档；
- 诊断信息不包含会话内容/密钥；
- 限流、容量、成本可控。

### 8.6 无障碍与国际化

- 悬浮球、树、会话输入可读屏；
- 长按语音有无障碍替代入口；
- 中英文文案同步。

## 9. v1 范围、非目标与路线

### 9.1 v1 范围（MVP）

| 模块 | v1 做什么 | 优先级 |
|---|---|---|
| 账号/服务 | 内置 + 自建；注册/登录；设备列表；单账号 | P0 |
| 设备 | 注册、默认名、当前设备改名、在线状态（P0）；撤销/移除（P1） | P0/P1 |
| 在场 | 手机悬浮球：长按语音 + 发送截图 + 手机 Computer Use | P0 |
| 统一树 | 本机工作区 + 其他设备/工作区/会话（远程只读 + 悬浮球任务可交互） | P0 |
| 远程会话 | 悬浮球派出的远程任务：实时看、输入、暂停、附件 | P0 |
| 跨设备调度 | 任意设备悬浮球派任务给其他设备标准后台 Agent；结果回传 | P0 |
| 文件 | 本机 ↔ 远程任务附件；手机照片 | P0 |
| 通知 | 任务状态、设备离线、等待确认 | P0 |
| 安全 | E2E、当前设备改名、撤销、敏感确认、手机提示 | P0 |
| 多端 | 手机优先；桌面按 D3 路线 | P0/P1 |

> **v0 是 v1 的裁剪，不改变本文的目标承诺。** 裁剪内容（无账号/内置服务/门户、树为「全部可看 + 任务会话可交互」、无工具级范围配置、审批可答者为两台）见 [16 §2.3](16-v0-plan.md) 与 [19](19-v0-decisions.md)；第 14 节的验收标准仍按 v1 写。

### 9.2 v1 明确不做

- 远程桌面/屏幕串流；
- 全量文件同步盘；
- 团队/家庭共享、RBAC、组织；
- 离线任务队列；
- 跨账号联邦/公开设备市场；
- 复杂计费/市场；
- 远程操作所有 App 的通用无人值守（手机被控仍以确认/安全为先）。

### 9.3 路线

| 阶段 | 名字 | 交付 |
|---|---|---|
| P0 | **Connect** | 账号/服务、设备注册、默认名、当前设备改名、在线状态、门户；插件登录 |
| P1 | **See** | 统一树只读、远程会话查看；手机悬浮球在场能力 |
| P2 | **Act** | 远程会话输入/暂停、悬浮球跨设备派发、文件双向 |
| P3 | **One** | 全部远程会话可交互、桌面统一体验（按 D3）、手机作为被控端 |
| P4 | **Scale** | 多用户/家庭、审计、权限、自建运维、生态 |

> v1 的交付范围是 **P0–P2 合并**：先能连、能看、能派任务、能传文件；P3/P4 明确不属于 v1。P1 的「在场能力」和「统一树」同期推进，因为手机悬浮球是产品的第一入口。

## 10. 端到端场景：林然的三台设备

> 本场景用于产品评审和验收：把 FR-A / FR-B 串成一条真实的一天。场景描述目标体验；v1 的具体裁剪见 9.1。桌面端的呈现形式取决于 D3；手机端按完整目标体验描述。
>
> 场景假设：D5 用户输入优先；D6 审批默认在发起设备、目标设备同步提示。若这两个决策改变，场景中的交互位置相应调整，任务本身不变。

### 10.1 场景设定

| 项 | 设定 |
|---|---|
| 人物 | 林然，35 岁，品牌顾问，一个人住、一个人工作 |
| 设备 | **书房 Mac**（MacBook Pro，macOS，DSH 桌面版 + 悬浮球）、**公司 Windows**（Windows 11 台式机，DSH 桌面版 + 悬浮球）、**随身手机**（Android，dsh-Go + 悬浮球） |
| 账号 | 内置服务（暂名 Orb Link），一个账号；后来换成自建 `https://mesh.linran.example` |
| 工作区 | Mac：品牌改版、设计说明；Windows：Q4 报价、客户资料；手机：相册、微信 |
| 前情（上周五） | 三台设备都装了 DSH + 悬浮球；在 Mac 上注册/登录内置服务；手机和 Windows 用同一账号登录；默认名 `Mac1` / `Windows1` / `Phone1`；分别在各自设备上改名为 `书房 Mac` / `公司 Windows` / `随身手机`；门户只读 |
| 默认规则 | 只有当前设备能改自己的名字；门户/其他设备只读；服务不存会话内容 |

### 10.2 07:40 手机：一句话处理眼前的屏幕

林然在厨房，手机上是客户王总的微信：一段地址 + 一张场地照片。她长按悬浮球，震动后说：

> “把王总发的地址记到公司 Windows 的《客户资料》里，再回他周三下午两点可以去看场地。”

她松手。悬浮球面板显示：

- 已收到语音：“把王总发的地址记到公司 Windows 的《客户资料》里，再回他周三下午两点可以去看场地。”
- 已附当前屏幕（一张缩略图，只有微信，没有悬浮球）。
- 正在看屏幕……

Agent 看到了微信内容，用手机 Computer Use 打开王总的消息，复制地址，回到聊天框起草回复。几秒后，悬浮球弹出确认：

> 回复王总：“周三下午两点我们可以过去看场地。” 发送？

她点“发送”。消息发出。悬浮球继续说：

> 地址已记下。正在让公司 Windows 写入《客户资料》。

手机的树里，`公司 Windows → 客户资料 → 新会话` 出现，状态“运行中”。十几秒后变成“完成”，悬浮球汇总：

> 已写入《客户资料》：王总地址、周三下午两点看场地；微信已回复。

她点开那条 Windows 会话，看了一眼写入结果，关掉。全程她没有切屏、没有截图、没有上传；悬浮球就在微信上面，她看得见它点了哪里。任务完成后手机通知栏有一条“跨设备任务完成”。

**覆盖：** FR-A1、A2、A3、A5、A6、B3、B5、B7、B10。

### 10.4 09:30 Mac：把两个文档分别派给 Windows 和本机

她在 Windows 上继续改报价单；Mac 的树里，`公司 Windows` 的会话实时更新。她在 Windows 上点开 Mac 的《设计说明》任务，看到照片插入结果；她给 Mac 的会话留了一句“第 3 页照片再大一点”，Mac 的本地任务继续处理。

她在 Windows 的设置里确认：本机名称 `公司 Windows`，其他设备只读；门户里三台设备都在线。

**覆盖：** FR-B2、B3、B4、B9、B10。

### 10.7 16:30 离线、失败、丢失手机

**离线：** 手机没电关机。Mac 的树里 `随身手机` 变成“离线 · 2 分钟前”。林然让悬浮球“把手机里另一张照片发过来”，悬浮球直接说：

> 随身手机离线，任务没有派发。要我等你手机上线再试吗？

它没有转圈，也没有假装成功。

**失败：** Windows 上的《Q4 报价单》被 Word 占用。Windows 任务失败，Mac 的树里显示“失败：文件被占用”。她点开会话，看到失败原因和“重试”；她在 Windows 上关掉 Word，点重试，任务成功。

**丢失手机：** 17:00，她发现手机落在出租车上了。她在 Mac 的互联设置里撤销 `随身手机`；树里该设备消失，所有到手机的任务断开。手机即使被人捡到，也无法再连上账号。她后来买了新手机，重新登录/注册，改名为 `随身手机 2`。

**敏感操作：** 在手机丢失前，悬浮球曾在手机上尝试打开银行 App 查余额；手机弹出“这次操作需要你确认”，她拒绝了，悬浮球停下并说“已停止，没有继续”。

**覆盖：** FR-A3、B2、B7、B8。

### 10.8 周末：换成自己的服务器

林然不想把设备信息放在我们的内置服务上。她在自己的 NAS 上部署了同一套互联服务，得到一个地址 `https://mesh.linran.example`。

她在 Mac 的悬浮球设置 → 互联里：

1. 退出内置服务；
2. 选“自建服务”，填 `https://mesh.linran.example`；
3. 在打开的网页里注册/登录；
4. 三台设备依次登录同一个自建地址；
5. 重新命名、确认在线。

之后，树、任务、文件、审批和内置服务完全一样；只是设备列表在她的服务器上。门户里只有设备和在线信息，没有会话内容；她可以随时导出/备份/停掉自己的服务。

**覆盖：** FR-B1、B9；NFR 自建/隐私。

### 10.9 19:00 一天结束：树就是工作记录

林然回到书房，Mac 的树里：

```
书房 Mac
 ├─ 品牌改版
 │    └─ 设计说明 v3（照片已插入）
 ├─ 设计说明
 └─ Q4 报价单-备份（标题红色）

公司 Windows
 ├─ Q4 报价
 │    ├─ 改报价单（完成，附件已回传）
 │    └─ 客户资料（完成）
 └─ 客户资料

随身手机（离线）
```

悬浮球汇总：

> 今天跨 3 台设备完成了 5 个任务：微信回复 + 客户资料、Windows 报价单、Mac 备份、手机照片插入、Windows 重试成功。文件都在对应会话里。

她点开每个任务都能看到：谁发起的、在哪台设备跑的、用了哪些工具、改了哪个文件、附件从哪来到哪去。没有云盘同步，没有远程桌面；她只是对悬浮球说了几句话。

**覆盖：** FR-B3、B5、B7、B10；产品原则“任务是会话，文件是附件”。

### 10.11 这个场景验证了什么 / 不验证什么

**验证：**

- 一个账号、三台设备、一棵树；
- 手机悬浮球的在场能力：语音 + 截图 + 当前屏操作；
- 跨设备派发：Mac → Windows、Mac → 手机；
- 远程会话：实时、暂停、插话；
- 文件双向：PDF 去 Windows、报价单回 Mac、手机照片回 Mac；
- 审批、离线、失败、撤销设备；
- 内置服务与自建服务；
- 多端一致：Mac / Windows / 手机都能看到同一批设备/任务。

**不验证：**

- 远程桌面/屏幕串流（产品明确不做）；
- 全量文件同步盘（明确不做）；
- 团队/RBAC/多用户；
- 离线任务队列；
- 跨账号联邦；
- 手机界面的远程无人值守操控（手机被控仍以确认/安全为先）。

**场景假设（若决策变化，场景相应调整）：**

- **D3**：桌面端按“自研桌面壳/完整统一树”描述；若最终是“官方 DSH + 插件”，树/主会话区的呈现会更受限，场景中的交互不变、入口形态变。
- **D4**：场景按“全部工作区/会话可见”描述；v1 若先只放悬浮球任务，10.3/10.6 中非任务会话先只读/占位。
- **D5**：用户输入优先，悬浮球等待/汇总。
- **D6**：审批默认在发起设备，目标设备同步提示。

## 11. 关键用户流程（摘要）


### 11.1 流程 A：手机悬浮球处理当前屏

1. 用户长按悬浮球说话；
2. 松手：转写 + 截当前屏（隐藏球）；
3. 消息（文字 + 截图）进入悬浮球对话；
4. Agent 看截图，调用手机 Computer Use；
5. 敏感步骤出现确认；用户可停止；
6. 完成后 Agent 汇总；用户可继续。

### 11.2 流程 B：Mac 派任务给 Windows

1. 用户在 Mac 悬浮球说「把 Windows 上 X 文档改蓝」；
2. 悬浮球判断需要 Windows；
3. 选择 Windows 设备/工作区，创建远程任务会话；
4. Mac 树里出现「Windows · workspace · 会话」；
5. Windows 后台 Agent 执行；Mac 树实时显示状态；
6. 用户可打开会话、暂停、插话；
7. 完成后结果回到 Mac 悬浮球，悬浮球汇总。

### 11.3 流程 C：手机照片进 Mac 文档

1. 用户在 Mac 悬浮球说「把手机里这张照片插到 Y 文档」；
2. 悬浮球调用手机后台 Agent 找照片；
3. 手机 Agent 返回照片附件；
4. Mac 悬浮球把照片作为附件派给 Mac/本地文档任务；
5. 完成后汇总，文件去向可见。

### 11.4 流程 D：在 A 看/管 B 的任务

1. 用户在 Mac 树里看到 Windows 会话运行中；
2. 点开，实时看消息；
3. 点暂停；
4. 在输入框发新指令；
5. 悬浮球也在等这个任务，结果同步。

### 11.5 流程 E：设备改名

1. 用户在 Mac 的「互联」设置改名为「书房 Mac」；
2. 保存；
3. 手机/Windows/门户刷新为新名字；
4. 手机/Windows/门户没有改名入口。

### 11.6 流程 F：离线/失败

1. Windows 离线；
2. Mac 树显示离线 + 上次在线；
3. 派发任务时明确「Windows 离线，未派发」；
4. 不转圈、不假装成功；
5. 设备回来后重连，树恢复。

## 12. 成功指标

### 12.1 激活

- ≥ 2 台设备登录同一账号的比例；
- 从登录到第二台设备可见的时间；
- 24 小时内完成第一次跨设备任务的比例。

### 12.2 使用

- 每周跨设备任务数；
- 远程会话打开次数；
- 用户暂停/插话比例（说明「可干预」被使用）；
- 文件双向传输次数/成功率。

### 12.3 可靠性

- 跨设备任务成功率（简单任务 ≥ 80%）；
- 远程会话重连成功率；
- 任务派发到开始执行的延迟；
- 设备离线检测延迟；
- 文件传输失败率。

### 12.4 信任

- 跨账号泄漏事件 = 0；
- 未授权跨设备动作报告 = 0；
- 设备撤销/断开使用情况；
- 自建服务比例；
- 安全审计覆盖。

### 12.5 满意度

- NPS/CSAT；
- 「像一台电脑」主观评分；
- 「愿意推荐给同样多设备的人」比例。

## 13. 开放问题与待决策

| 编号 | 问题 | 影响 | 建议 |
|---|---|---|---|
| D1 | 目标用户：极客/自建优先，还是大众/内置优先？ | 默认体验、定价、文档、运维 | 先服务多设备 DSH 用户，内置降低门槛、自建满足隐私 |
| D2 | 产品定位：悬浮球插件的一个功能，还是独立平台/品牌？ | 命名、入口、路线 | 作为悬浮球的「超级互联」能力，但独立品牌化 |
| D3 | 桌面端承诺：官方 DSH + 插件，还是自研桌面壳？ | 统一树/主会话区能否原样实现 | 必须早拍板；插件路线要接受形态折中。**v0 已定：官方 DSH + 插件 + 独立 Mesh 窗口，不动官方左栏（[19](19-v0-decisions.md)）** |
| D4 | 树的边界：所有 DSH 会话，还是 v1 先只放悬浮球任务？ | 数据量、UI 复杂度、隐私 | v1 先「本机 + 远程任务」；v1.1 扩全部工作区。**v0 已定：全部设备/工作区/会话可看，只有派出的任务会话可输入（[19](19-v0-decisions.md) P2）** |
| D5 | 用户和悬浮球同时操作远程会话，谁优先？ | 交互语义、冲突 | 用户输入优先；悬浮球等待/汇总 |
| D6 | 审批放哪：发起设备、目标设备，还是两边？ | 安全与顺滑 | 默认发起设备；敏感操作目标设备也提示 |
| D7 | 文件模型：任务级附件，还是同步盘？ | 产品边界 | 明确任务级附件，不做同步盘。**v0 已定：任务级附件；结果文件落在发起端的任务卡与附件区，不进目标会话的原生附件** |
| D8 | 账号范围：只支持单人，还是家庭/团队？ | 账号/权限/计费 | v1 单人；后续再议 |
| D9 | 服务模式：内置收费、自建免费？开不开源？ | 商业/信任 | 内置订阅 + 自建免费/开源可讨论 |
| D10 | 第一个 killer demo | 传播/验证 | 「Mac 一句话，Windows 改文档 + 手机照片进 Mac 文档」 |
| D11 | 手机是否允许被远程操作？ | 安全/体验 | 允许，但默认关、强提示、敏感确认 |
| D12 | 远程后台 Agent 用标准模式，还是允许目标端 Computer Use？ | 能力/安全 | 默认标准；GUI 任务按需选 CU。**v0 已定：进来的任务固定 `standard`，不做 GUI/CU；验收文档用文本或 Markdown** |

## 14. 验收标准（v1）

### 14.1 账号与服务

- [ ] 用户能在内置服务注册/登录；
- [ ] 用户能填自建服务地址并登录；
- [ ] 门户能看到设备列表/在线状态；
- [ ] 门户不能改设备名、不能看会话内容；
- [ ] 退出登录后本地 DSH 不受影响。

### 14.2 设备

- [ ] 两台设备登录同一账号后互相可见；
- [ ] 默认名符合平台规则；
- [ ] 当前设备能改名，其他设备/门户只读；
- [ ] 改名后所有端同步；
- [ ] 设备离线有明确状态；
- [ ] 撤销设备后无法再被调用。

### 14.3 统一树

- [ ] 本机工作区在上，其他设备在下；
- [ ] 设备 → 工作区 → 会话三层；
- [ ] 运行/等待/空闲/离线状态可见；
- [ ] 远程会话可打开；
- [ ] 断线重连后树恢复。

### 14.4 远程会话/任务

- [ ] Mac 悬浮球能派任务给 Windows；
- [ ] Windows 会话出现在 Mac 树里；
- [ ] Mac 能实时看到输出；
- [ ] Mac 能暂停；
- [ ] Mac 能发新指令；
- [ ] 结果回到 Mac 悬浮球；
- [ ] 目标离线/失败有明确提示。

### 14.5 文件

- [ ] 本机文件能作为附件发给远程任务；
- [ ] 远程结果能作为附件回传；
- [ ] 手机照片能参与任务；
- [ ] 文件来源/去向可见；
- [ ] 大文件有进度/失败提示。

### 14.6 在场能力

- [ ] 长按说话、松手发送；
- [ ] 发送时附带当前屏截图；
- [ ] 截图不含悬浮球；
- [ ] 安全页面不截屏；
- [ ] Agent 能对当前屏操作；
- [ ] 敏感操作需确认；
- [ ] 用户能随时停止。

### 14.7 安全

- [ ] 会话内容端到端加密；
- [ ] 服务端不存明文；
- [ ] 改名只允许当前设备；
- [ ] 跨设备动作有范围/确认；
- [ ] 手机被控有提示；
- [ ] 一键停止/断开可用。

### 14.8 体验

- [ ] 桌面/手机核心概念一致；
- [ ] 中英文一致；
- [ ] 无障碍可用；
- [ ] 失败/空状态有可读文案；
- [ ] 新用户能在 10 分钟内完成「登录 → 看到第二台设备 → 第一次跨设备任务」。

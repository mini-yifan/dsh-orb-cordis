# 悬浮球超级互联 v0 实施计划

> 状态：Draft v0.2（计划对齐）
> 日期：2026-11-10
> 范围：单租户自建互联 v0，**3–5 台设备**（Mac + Windows + Android 手机，另加 1–2 台）互联验收；Android 悬浮球先独立验收，再入网
> 关联：[14-interconnect-prd.md](14-interconnect-prd.md)、[15-existing-assets.md](15-existing-assets.md)、[17-implementation-plan.md](17-implementation-plan.md)
> 说明：本文只定计划、范围、里程碑、验收与风险；技术细节见 17

## 0. 计划摘要

### 0.1 这一版要做什么

- **不做账号体系**：没有注册/登录/多用户；一个自建服务 = 一个信任域。测试阶段只有一个用户，但**必须支持 3–5 台设备同时互联**。
- **自建服务部署在阿里云 Linux 公网服务器**：管理员页面 + 设备配对 + 在线状态 + 中继。
- **管理员手动加设备**：每台设备一个一次性配对码；设备输入码后接入。
- **电脑先通**：Mac、Windows（加一台电脑或虚拟机凑足 3 台）互相看到工作区/会话，能实时看、输入、停止；悬浮球能跨设备派后台 Agent；文件双向。
- **自定义 Mesh UI**：在悬浮球插件里做多设备树/会话界面；**官方 DSH 左栏尽量不改**。
- **Android 悬浮球**：基于 dsh-Go 做手机版悬浮球。悬浮球 Agent 只用精简工具集（Shell、网页检索与抓取、向用户提问、dsh-Go 手机操控），需要后台干活时交给 dsh-Go 的**标准模式**。先独立验收，再作为完整节点**入网**。
- **v0 先不做**：账号/注册/登录、内置服务、多用户、官方 DSH 左栏统一树、审计报表、P2P/TURN、离线任务队列、超过 5 台设备。

### 0.2 v0 完成定义

v0 分三段验收，全部通过才算完成；全程没有登录页。下面是摘要，逐条通过条件以第 7 节为准。

**第一段：电脑互联（3 台电脑，Mac + Windows + 第三台电脑或虚拟机；逐条见 7.1）**

1. 阿里云服务器部署完成，管理员页面可添加设备、生成配对码；
2. 三台电脑用各自配对码接入，管理页能看到设备名、平台、在线、上次在线；
3. 每台电脑的 Mesh UI 都能看到「本机 + 其他所有在线/离线设备 → 工作区 → 会话」；
4. 打开任意一台对端的会话，实时看消息/工具/状态；
5. 能给对端会话发新指令、停止当前这一轮；
6. Mac 悬浮球能派后台 Agent 到 Windows 执行，Mac 实时看到，结果回到 Mac；同时能往第三台派另一个任务；
7. 文件双向：Mac 发给 Windows，Windows 的结果文件回到 Mac，作为该任务的附件；
8. 远程任务需要审批或提问时，在发起设备上能答；目标设备本机也能答，先答者生效；
9. 改名/离线/撤销：当前设备改名、其他设备只读；离线 30 秒内可见；目标离线时任务不派发；撤销后不能连；
10. 全程 E2E（服务器不解密），无账号/登录。

**第二段：Android 悬浮球（独立；逐条见 7.2）**

1. 手机上出现全局悬浮球；
2. 长按说话、松手发送；
3. 发送时附带当前屏截图；
4. 悬浮球 Agent 只带精简工具集（加一个只负责交出任务的派后台工具），能对当前屏做 Computer Use，敏感操作确认；
5. 有 Orb 面板（对话/状态/停止/历史/新建）；
6. 需要文件、命令、长任务时交给本机**标准模式**后台 Agent，完成后回到 Orb；
7. 继承 dsh-Go 支持的 Android 机型/系统范围。

**第三段：手机入网（5 台，Mac + Windows + 手机 + 另外 2 台；逐条见 7.3）**

1. 手机用配对码接入，所有电脑的 Mesh UI 都能看到手机及其工作区/会话；
2. 手机 App 里能看到所有电脑的树，能打开远程会话、看实时、输入、停止；
3. 手机悬浮球能把任务派给 Windows，结果回到手机悬浮球；
4. Mac 能让手机找一张照片并作为附件取回（不远程操作手机界面）；
5. 其他设备默认**不能**操作手机屏幕；打开开关后，手机有明显提示且敏感操作仍要手机上确认；
6. 5 台设备同时在线时，树、会话、派发、文件都正常（第 4、5 台可用另一台电脑/虚拟机、x86_64 Android 模拟器或第二台手机）。

## 2. v0 产品范围

### 2.1 做

**服务端（阿里云 Linux）**

- 管理页：管理员口令登录；添加/删除设备、生成/作废配对码、改名、撤销、查看在线/连接记录；
- 设备注册/配对：一次性配对码、设备公钥、设备 token；
- 在线状态/心跳（30 秒内判离线）；
- 中继：**同一台设备同时连多台设备**的会话流、控制消息、文件传输；
- E2E：服务器只转发密文；
- 限流、日志、备份、监控、TLS。

**Mac / Windows 设备端**

- 悬浮球插件里的「互联」模块：填服务器地址、证书指纹、配对码，显示当前设备名/在线；「允许被其他设备调用」开关（默认开）；
- 设备身份/密钥、连接、重连；
- 暴露本机 DSH 工作区/会话给 Mesh；
- **同时连接所有对端设备**、拉取工作区/会话、订阅实时流；
- 远程会话：看、输入、停止；远程审批/提问可在本机答；
- 跨设备后台 Agent：`device_agent` 任务，派发前检查目标在线；
- 文件双向：随任务发出、结果文件回传为会话附件；
- 任务状态/通知/错误。

**Mesh UI（自定义）**

- 从悬浮球菜单/设置打开独立的 Mesh 窗口；
- 左侧：设备 → 工作区 → 会话树（3–5 台设备）；
- 右侧：会话 transcript、工具状态、审批/提问卡、输入框、停止；
- 顶部：在线状态、当前设备、刷新/重连；
- 任务卡、附件、文件去向；
- 中文/英文文案、跟随系统深浅色、键盘可操作；
- **不修改官方 DSH 左侧工作区**。

**Android 悬浮球**

- 全局悬浮球；长按录音/松手发送；发送时截图；
- 悬浮球 Agent 精简工具集：Shell、网页检索与抓取、向用户提问、dsh-Go 手机操控；外加只负责交出任务的派后台工具；
- Orb 面板/停止/历史/新建；
- 本机后台 Agent（dsh-Go 标准模式），完成后回到 Orb。

**手机入网**

- 手机本机引擎装上与电脑相同的互联插件，成为完整节点；
- App 内互联页：配对、本机名、设备树、远程会话（看/输入/停止/审批）；
- 悬浮球可 `device_agent` 派任务给电脑；
- 电脑可派任务给手机后台 Agent，手机文件（照片）作为附件回传；
- App 互联页里的开关：「允许其他设备操作本机屏幕」（默认关）、「允许被其他设备调用」（默认开）、「访问手机文件」入口（沿用 dsh-Go 设置，取照片时需要）。

### 2.2 不做（v0）

- 账号/注册/登录、OAuth、多用户、团队；
- 内置服务（只做自己的自建服务）；
- 官方 DSH 左栏统一树、主聊天区多 Host；
- 审计报表、计费；
- 超过 5 台设备、P2P/TURN（先 Relay）；
- 远程桌面、全量文件同步、离线任务队列；
- 跨账号联邦；
- 手机悬浮球面板内的完整渲染（Markdown/代码高亮）。

### 2.3 与 PRD 的差异

| PRD | v0 做法 |
|---|---|
| 账号/登录/内置服务 | 不做；单租户自建，管理员口令 + 配对码 |
| 设备命名 | 当前设备改名；管理员后台可改；普通页面只读 |
| 统一树 | 自定义 Mesh UI；DSH 左栏不变；手机在 App 内 |
| 远程会话可交互 | 全部远程会话可看、可输入、可停止（比 PRD v1「只交互悬浮球任务」更宽） |
| 暂停 | 停止当前这一轮，补消息继续 |
| 手机作为被控端 | 入网后可被派后台任务；操作手机屏幕默认关 |
| 审批/审计 | 审批与提问可跨设备答；审计只记连接层元数据 |
| 门户 | 管理页走 SSH 隧道访问，不对公网开放 |

## 3. 逻辑架构（计划级）

```
                 阿里云 Linux（公网 IP，HTTPS/WSS）
        ┌──────────────────────────────────────────────┐
        │ 管理页（仅 127.0.0.1，经 SSH 隧道访问）          │
        │ 设备注册 + 配对码 + 在线状态 + 连接记录          │
        │ E2E 中继（一台设备可同时连多台）                 │
        └──────▲─────────────▲─────────────▲──────────┘
               │ 出站 WSS     │ 出站 WSS     │ 出站 WSS（均为 E2E）
        ┌──────┴──────┐ ┌────┴──────┐ ┌────┴──────────────┐
        │ Mac          │ │ Windows    │ │ Android 手机       │
        │ DSH + 悬浮球  │ │ DSH + 悬浮球│ │ dsh-Go + 悬浮球    │
        │ 互联插件      │ │ 互联插件    │ │ 本机引擎内互联插件 │
        │ Mesh 窗口     │ │ Mesh 窗口   │ │ App 内互联页       │
        └─────────────┘ └───────────┘ └───────────────────┘
        （第 4、5 台：另一台电脑/虚拟机或另一台手机，结构相同）
```

要点：

- 设备只**出站**连接服务器，不开公网入站端口；
- 每台设备同时连接其他所有在线设备（5 台时每台最多 4 条连接）；
- 服务器只做管理/配对/在线/中继，**不解密会话/文件**；
- 手机用与电脑**同一套**互联插件（跑在 dsh-Go 本机引擎里），不另写一套协议。

> 以上是逻辑图，不是接口设计；具体协议/存储/部署见 17。

## 4. 关键流程

### 4.1 管理员添加设备

1. 管理员经 SSH 隧道打开管理页，用管理员口令登录；
2. 新增设备（备注/平台）；
3. 生成一次性配对码（30 分钟有效，只能用一次）；
4. 在设备「互联」设置里填服务器地址 + 配对码；
5. 设备生成密钥、提交配对码/公钥；服务器校验、绑定设备、发设备 token；
6. 设备上线，管理页显示在线；
7. 管理员可撤销/改名/重新生成配对码。

### 4.2 设备上线/在线状态

- 设备启动后连服务器，并连接其他所有在线设备；
- 心跳 10 秒一次，20 秒无响应判离线，各端最迟约 27 秒看到；
- 管理页与 Mesh UI 显示：名称、平台、在线、上次在线；
- 离线设备上线后自动重连，树恢复。

### 4.3 Mesh UI

1. 从悬浮球菜单/设置打开 Mesh；
2. 显示「本机 + 其他设备」→ 工作区 → 会话；
3. 点远程会话：拉取历史 + 订阅实时；
4. 输入/停止；审批/提问卡；
5. 任务卡/附件/状态；
6. 离线设备显示缓存和「离线 · 上次在线」。

### 4.4 跨设备后台 Agent

1. 悬浮球收到任务；
2. 判断目标设备（用户指定/按名称/平台）；不确定就问；
3. 目标离线 → 直接告诉用户「未派发」，不建会话；
4. 用户没指明工作区 → 列出目标设备的工作区让用户选；
5. 调用 `device_agent`：目标设备、工作区、任务、附件；
6. 目标设备创建**标准模式**后台会话；
7. 发起设备 Mesh UI 出现该会话，实时显示；需要审批/提问时在发起设备弹卡；
8. 用户可停止/插话；
9. 完成后结果文件回传为会话附件，悬浮球汇总；
10. 失败给出原因，可对同一会话重试。

### 4.5 文件双向

- 本机文件 → 上传到目标会话 → 目标 Agent 拿到路径；
- 目标 Agent 的结果文件 → 回传到发起设备 → 记为该任务的附件（Mesh UI 任务卡与悬浮球里可见），显示来源/去向；
- 有进度；失败可整份重试；经中继单文件上限 20 MB（可配置）；
- 手机照片：手机打开「访问手机文件」后，后台 Agent 从相册取文件回传。

### 4.6 Android 悬浮球

1. 全局悬浮球；
2. 长按录音，显示波形；
3. 松手：转写 + 截当前屏（隐藏球）；
4. Orb 面板显示消息 + 截图；
5. 悬浮球 Agent（精简工具集）用手机操控对当前屏操作；
6. 敏感操作确认；可停止；
7. 需要文件/命令/长任务时派给本机标准模式后台 Agent，完成后回到 Orb。

### 4.7 手机入网

1. 手机 App「互联」页填服务器地址 + 配对码；
2. 手机本机引擎里的互联插件完成注册、上线；
3. 所有设备的树里出现手机；手机 App 里出现所有设备；
4. 手机悬浮球可派任务给电脑；电脑可派任务给手机后台 Agent；
5. 其他设备发起的会话默认不能调用手机屏幕操作工具。

### 4.8 撤销/离线/失败

- 管理员撤销设备 → token 失效、所有连接断开、各端树里消失；
- 设备离线 → 30 秒内各端显示离线；派发前检查，离线就不派发；
- 派发后目标断线 → 任务显示「状态未知」，重连后按会话对账，不重复派发；
- 远程任务失败 → 可读原因 + 重试；
- 不静默失败、不假装完成。

## 5. 工作分解（Workstreams）

### WS1 服务端 / 管理页 / 配对 / 安全

**交付：**

- 阿里云 Linux 部署（Docker）；TLS 终止；只开 443；安全组/防火墙；
- 管理页（仅 127.0.0.1，经 SSH 隧道）：管理员口令、设备 CRUD、配对码、改名、撤销、连接记录；
- 设备注册/配对/token/心跳；
- **一台设备同时连多台设备**的中继；
- 限流、日志、备份、监控、告警；
- 公网安全基线：管理员口令强度、配对码 TTL/一次性、失败限流、默认拒绝。

**退出标准：** 管理员能添加 3 台设备并看到在线（5 台在 M4 回归）；任意两台之间能同时建立连接；设备能配对/重连；服务器抓包看不到会话明文；公网端口上没有账号登录相关接口。

### WS2 Mac / Windows 设备端

**交付：**

- 悬浮球插件「互联」设置：服务器地址、配对码、设备名、在线、设备列表；
- 设备身份/密钥/token/重连；
- 本机 DSH 工作区/会话暴露；
- 同时连接所有对端、工作区/会话拉取、实时订阅；
- 远程会话输入/停止；远程审批/提问应答；
- `device_agent` 任务；
- 文件上传/回传；
- 状态/通知/错误。

**退出标准：** 三台电脑能互相看到工作区/会话；能打开、输入、停止、答审批；任务/文件跑通。

### WS3 Mesh UI（自定义）

**交付：**

- 从悬浮球菜单/设置打开的 Mesh 窗口（普通窗口）；不改 DSH 左栏；
- 设备 → 工作区 → 会话树；
- transcript/工具状态/审批与提问卡/输入/停止；
- 任务卡/附件/文件去向；
- 在线/离线/重连；
- 中文/英文、深浅色、键盘操作。

**退出标准：** 不打开官方 DSH 工作区，也能在 Mesh UI 完成对 3 台以上设备的看/输入/停止/审批/任务；切换中英文、深浅色后界面正常；只用键盘能选中会话并发出一条指令。

### WS4 跨设备 Agent / 文件

**交付：**

- `device_agent`：目标设备、工作区、任务、附件、等待、结果、取消；派发前在线检查；
- 目标标准后台会话；
- 完成通知/结果汇总/结果文件回传；
- 文件进度、大小上限、整份重试、清理；
- 用户插话/停止与悬浮球等待的协调。

**退出标准：** Mac 一句话，Windows 后台 Agent 完成文本文档任务并回传结果文件；同时派给第三台不互相干扰。

### WS5 Android 悬浮球

**交付：**

- dsh-Go 分支/修改；
- 全局悬浮球；长按语音/松手发送；发送时截图；

- Orb 面板（最小版从第一步就有）/停止/历史/新建；
- 本机标准模式后台 Agent + 完成通知；
- 敏感操作确认。

**退出标准：** 在 dsh-Go 支持的 Android 机型上，能完成「长按说话 → 截图 → 当前屏操作 → 结果」与「派后台 → 完成回到 Orb」两个闭环。

### WS6 手机入网

**交付：**

- 手机本机引擎加载互联插件；

- 手机作为被调用端：后台任务、文件回传、屏幕操作开关（默认关）。

**退出标准：** 7.3 第 1–5 条通过（第 6 条规模验收在 M4）。

## 8. 公网服务器安全 / 运维

### 8.1 阿里云部署

- Linux；Docker；
- 公网 IP 直连，不买域名、不备案；TLS 用自签证书，客户端固定指纹（若能签到公网 IP 的公开证书，可以用，但仍固定指纹）；
- 只开放 443；SSH 限来源 IP、只用密钥；
- 安全组最小开放；限流。

### 8.2 管理员页面

- 只监听服务器本机 127.0.0.1，经 SSH 隧道访问；
- 强管理员口令（≥ 16 位随机）；
- 不与设备 API 混用 token；
- 管理员操作记录；
- 默认拒绝、失败限流；
- 不在页面显示会话内容/密钥。

### 8.3 设备配对

- 管理员生成一次性配对码（30 分钟、一次）；
- 设备提交码 + 公钥；服务器绑定；
- 码只存哈希；失败限流；
- 设备 token 可撤销；
- 设备名称默认 + 当前设备改名 + 管理员后台改名（特权，不锁定）。

### 8.4 E2E

- 公网 v0 **必须 E2E**；TLS 不是 E2E；
- 复用 ds-harness-remote 的 Noise 实现，不自创加密；
- 服务器只转发密文；
- 设备公钥固定/校验；
- 密钥只在设备本地。

### 8.5 运维

- 日志（不含内容）、指标、告警；
- 备份/恢复（设备元数据/连接记录；不含会话）；
- 升级/回滚；
- 证书续期；
- 事故响应/撤销流程；
- 带宽监控（5 台设备的中继流量）。

## 9. 风险与依赖

| 风险 | 影响 | 应对 |
|---|---|---|
| 公网服务器被攻击/管理员页被撞库 | 设备被控 | 管理页不出公网、强口令、限流、最小端口 |
| 配对码泄漏/复用 | 未授权设备接入 | 一次性、短 TTL、哈希、限流、管理员可见 |
| E2E 实现复杂/不兼容 | 安全不达标 | 复用成熟 Noise/协议；不自创 |
| DSH 桌面 UI 限制 | 树/会话无法进官方主界面 | 自定义 Mesh UI；DSH 左栏不变 |
| **多设备同时连接** | 现有服务端/客户端是「一次连一台」 | M0 前先改服务端与客户端连接管理并验证（见 17） |
| 远程审批/提问 | 任务卡住 | B0 验证 DSH 自带的远程应答；不通再自建转发 |
| 文件路径/大小/清理 | 文件体验差 | 任务级附件、进度、上限、整份重试、清理策略 |
| **手机引擎跑互联插件** | 手机无法入网 | A5 前先在手机引擎里加载验证；只用 Relay，不依赖 WebRTC 原生库 |
| 手机引擎在后台被回收 | 手机掉线 | 沿用前台服务保活；掉线明确显示离线 |
| 远程操作手机屏幕 | 安全 | 默认关；打开后明显提示；敏感操作仍在手机确认 |
| Android dsh-Go AGPL/上游兼容 | 分发/合并风险 | 先自用/分支；分发前做许可评估 |
| 阿里云服务器 12/10 到期、2C2G | 中途断服 | 现在续费；5 台设备 Relay 够用，监控带宽 |
| 范围蔓延 | 延期 | v0 排除项写死；变更走决策 |

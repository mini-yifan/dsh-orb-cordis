# 悬浮球划词需求

> 修订日期：2026-10-31。本文只记录已经约定的交互效果，不涉及实现方式。
>
> 划词功能曾因缺陷于 2026-09-30 全面下线（见 [04-addenda.md](04-addenda.md) 第 8 节）。本文是重新放开前重新约定的完整需求；与下线前的旧行为不一致的地方，以本文为准。

在任意应用里选中一段文字，悬浮球旁边出现一条工具条，提供搜索、翻译、发给 AI 三个动作。三个动作通向三个完全不同的去处：搜索交给浏览器，翻译在悬浮球里当场出结果且不打扰当前对话，发给 AI 进入正常对话并带上屏幕截图。

## 1. 触发

- 在任意应用里**拖选**一段文字后松手，工具条出现。
- **双击**选词、**三击**选段同样触发；单击不拖动不触发。
- 划词发生时不抢当前应用的光标焦点：原应用仍是前台应用，可以继续打字、继续滚动。
- 工具条出现在**选区附近**，并避开选区本身，不遮挡刚选中的文字；靠近屏幕边缘时自动收到屏幕内。
- 以下情况工具条不出现：
  - Agent 正在执行任务（此时选中文字没有任何反应，不弹任何东西）。
  - 当前应用就是悬浮球自己。
  - 划词开关关闭。
  - 读不到选中的文字。
- 工具条出现后，下列动作让它消失：鼠标在别处按下、滚轮滚动、按下任意键、切换到别的应用、点了其中某个按钮。
- 工具条上带一个目标语言下拉（中文 / English），选择立即生效并记住，下次仍是这个选择。

## 2. 搜索

点「搜索」。系统浏览器打开搜索结果的页面，搜索词就是选中的文字。悬浮球不展开、不参与，当前对话完全不受影响。工具条随即消失。

## 3. 翻译

点「翻译」。选中文字被译成工具条上选定的目标语言，结果显示在悬浮球里。

### 3.1 体感与 Agent 执行任务一致

从用户看到的效果看，翻译这一轮和悬浮球 Agent 接了一个任务在干活**没有区别**：

| 表现 | 翻译时的效果 |
|---|---|
| 面板 | 自动展开，并固定在屏幕上，不会因为鼠标移开而收起 |
| 外观 | 球进入工作态（动图播放、过程区展开） |
| 停止按钮 | 出现。点一下就停下输出，已输出的译文保留 |
| 输入框 | 隐藏，翻译期间不能打字、不能发送新指令 |
| 历史、新建 | 锁住，不能切换对话 |
| 结束时 | 停止按钮消失，输入框恢复可输入，历史、新建解锁 |
| 结束后 | 保持固定 30 秒（时长可在设置里改，5–600 秒），到时间自动取消固定，回到悬停展开、移开收起的常态 |

固定的计时从翻译结束时开始算。计时期间鼠标划过、移开都不影响；用户在球上做了操作（打字、发送、切换）会重新计时。

### 3.2 显示框里出现什么

显示框自上而下依次出现两块内容：

1. 一个用户气泡：一句翻译要求，加上选中的原文。
2. Agent 的回复：译文本身，逐字流式出现。

译文按普通 Agent 回复的样式渲染，Markdown、代码块、公式照常。

### 3.3 不进入对话上下文

这一问一答**不进入对话历史，也不进入上下文**：之后的任何一轮对话里，模型都不知道这次翻译发生过，翻译不占上下文长度，不产生费用之外的任何影响。

但显示框里看得到：

- 把面板收起再展开，译文还在。
- 应用重启之前，这段内容一直留在显示框里。
- 用户在输入框里接着问「刚才那个词什么意思」，模型**不会**知道指的是哪次翻译——这是这个设计的既定代价，用户需要自己说明。

### 3.4 未计入对话的标记

每一段翻译的用户气泡与译文都带一个可见标记，说明这段内容不属于当前对话。用户据此可以分辨哪些内容模型看得见、哪些看不见。

### 3.5 连续翻译

再划一次词、再点翻译，新的译文**追加**在旧译文下面，像聊天记录一样往下排，不覆盖上一次的结果。用户可以往回翻看之前的翻译。

对话真正轮换时（切换历史对话、新建对话），显示框清空，翻译记录一并清掉。

### 3.6 翻译与语音的关系

翻译期间**不启动语音输入**：麦克风完全关闭，系统不显示麦克风占用指示。用户不能靠说话打断或追加。

译文**不朗读**：即使设置里打开了语音播报，翻译的原文和译文都不会被读出来。

翻译结束后，语音恢复成固定状态下的正常行为。

### 3.7 长度上限

和悬浮球的输入框一致。选中的文字过长时截断，并在气泡里明确标出被截断了。

## 4. 发给 AI

点「发给 AI」。

### 4.1 输入框上方的选区条

悬浮球展开，输入框上方出现一条窄条，显示这次选中的文字（过长时省略显示，但完整内容会被带上）。

### 4.2 补上自己的要求

用户在输入框里打字，或直接说话（语音输入），表达自己要对这段文字做什么。发送时，**选中的文字和用户的要求一起**进入当前这一轮对话。

球上原有的语音输入在这个环节照常可用。

### 4.3 带上屏幕截图

和这个悬浮球平时的每一轮对话一样，发送时自动带上当前屏幕的截图，Agent 能看到用户当时正在看什么。

### 4.4 这是一轮正常对话

和普通的一轮对话完全一样：

- 用户气泡里是用户自己写的那句话（选中的文字作为附件一并进入，不在气泡里重复铺开）。
- 这一轮写进对话历史，之后可以回看、可以接着追问。
- Agent 的回复会进入语音播报（如果语音播报开着）。

### 4.5 取消选区

选区条右上角有关闭按钮。点掉之后，这一轮就只是普通对话，选中的文字不再被带上。

## 5. 开关与设置

- 划词工具条**默认开启**。
- 可以在两处关闭它：悬浮球右键菜单里的「划词工具栏」，以及主窗口「悬浮球」设置页里的开关。两处联动。
- 关闭后，在任何应用里划词都不再出现工具条，已经打开的也立即消失。
- 目标语言、固定时长这两项各自记住，与划词开关无关。
- 系统权限不齐全时（macOS 需要辅助功能授权），设置页明确说明划词当前不可用，并给出授权入口，而不是让用户以为功能坏了。

## 6. 已知限制

- 只支持在有辅助功能接口的应用里划词。图片里的文字、扫描件、部分终端界面读不出选中内容，此时不出现工具条，也不做任何兜底尝试。
- Agent 正在执行任务时不响应划词。同一时刻只处理一件事。
- 翻译记录只在本次运行期间保留，重启应用后不再出现。
- Windows 与 macOS 行为一致；Linux 上没有悬浮球，也就没有划词。

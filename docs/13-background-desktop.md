# 后台桌面操作能力 需求文档

> 状态：已确认（2026-11-07 修订：允许操作前台窗口，改为彩带提示）
> 日期：2026-11-07
> 范围：`dsh-orb` 插件（悬浮球 + 后台 agent），不改变前台 Computer Use 模式
> 本文只描述产品形态与需求，不涉及技术实现

## 1. 一句话

让后台 agent 能像人一样操作桌面软件，不碰鼠标、不抢焦点；它操作的每一个窗口都会亮起一条暖色彩带，用户随时看得见是谁在动。它不能向用户提问，做不到的事交回前台。

## 2. 背景与问题

当前悬浮球有两个角色：

- **前台 agent**：Computer Use 模式，能看屏幕、能操作软件，但必须占用屏幕和鼠标，用户只能等它做完。
- **后台 agent**：标准模式，能读写文件、跑命令、上网，**碰不了界面**。

结果是一个长任务被切成两半：后台把文件做完，停下来，通知前台；前台再切回界面部分一步步点。用户看到的就是"它做一会儿、停一下、再动一下"。

问题不在后台不够聪明，在于**后台没有一双手**。

## 3. 目标

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 后台能独立完成包含界面操作的任务 | 一个"写文档并发出"的端到端任务，全程不需要前台接手 |
| G2 | 后台操作界面时，不打断用户正在做的事 | 用户不切换窗口、不丢焦点、不丢正在进行中的输入 |
| G3 | 用户装完插件即可使用，零额外操作 | 不下载附加组件、不安装运行时、不配置路径、不出现命令行窗口 |
| G4 | Windows 与 macOS 体验一致 | 同样的任务在两边都能完成，用户流程相同 |

## 4. 非目标

- 不改变前台 Computer Use 模式的任何现有行为与体验。
- 不做第二套"后台截图识别"方案；后台对界面的理解只依赖软件暴露的结构化信息，不依赖像素。
- 不突破系统权限：系统不允许的操作就是不允许，不采用非常规手段强行置前或提权。
- 不做远程控制、不做多设备、不做无人工厂。
- 不替用户做不可逆的决定（见 D6）。

## 5. 用户与场景

**场景一：从文档到发出**
用户说"把这份资料整理成 Word，发给张老师"。
后台写完文档，直接在办公软件里打开、排好格式、保存；再在该沟通软件里找到人、附上文件、发出。全程用户可能正在浏览器里看别的东西，屏幕上只有一次短暂的目标窗口置前。

**场景二：批量整理**
用户说"把这批发票按月份归档到对应文件夹"。
后台打开文件管理器，新建文件夹，逐个移动。文件管理器全程在后台，用户不被打扰。

**场景三：做不到的时候**
后台需要操作一个用户正在打字的软件。
它不碰那个软件，先换一条路（改用文件、命令、另一个软件）；都不行，就停下，把"我需要在这个软件里点一下发送，但用户正在使用它"交回前台；前台向用户确认后，或者自己完成，或者给后台一次临时许可。

## 6. 产品形态

- **两个模式并列存在**：前台 Computer Use 模式（不变）、后台桌面模式（新增）。
- **后台模式 = 标准模式的全部能力 + 桌面操作能力**。它仍然是一个可以读写文件、跑命令、上网的工作会话，只是多了一双手。
- **用户通过前台发起**：用户在悬浮球里提出需求，前台判断这段活适合交给后台，就派给后台。用户感知上是"这件事交给它去办了"，而不是"我要手动开一个新模式"。
- **模式在选择器里可见**：用户也能自己新建一个后台桌面模式的会话（不是隐藏能力）。
- **安装即用**：装完插件，两个模式都可用。没有第二次下载、没有安装向导、没有环境配置。
- **平台**：Windows 与 macOS。

## 7. 核心需求

### A. 能力

| 编号 | 需求 |
|---|---|
| A1 | 后台模式必须具备标准模式的全部能力（文件、命令、网页、技能等） |
| A2 | 后台模式必须具备桌面操作能力：查看软件界面结构、点击、输入文本、按键、滚动、等待界面变化、打开/关闭软件、切换窗口 |
| A3 | 后台的操作对象是"软件里的可操作元素"，不是屏幕坐标；同一元素在不同时刻应能被稳定识别 |
| A4 | 界面变化后，旧的定位信息必须失效，不得凭旧信息继续操作 |

### B. 操作与边界

| 编号 | 需求 |
|---|---|
| B1 | **默认静默**：不移动鼠标、不抢键盘焦点、不切换前台应用 |
| B2 | 后台可以操作任何软件，**包括用户正在使用的、位于最前面的窗口**；不需要事先征求许可 |
| B3 | 操作目标窗口时，必须在该窗口四周显示一条彩带（见 C 节），让用户知道此刻是谁在操作 |
| B4 | 同一时刻，同一个软件只允许一个后台任务操作；不同软件可以并行 |
| B5 | 前台模式正在做物理输入（移动鼠标、按键）时，后台不得同时操作同一个软件；其余情况两者互不阻塞 |
| B6 | 后台不得读取剪贴板、系统通知等与当前任务无关的用户内容 |

### C. 彩带

| 编号 | 需求 |
|---|---|
| C1 | 彩带是"后台正在操作某个窗口"的唯一可视信号，默认开启，不提供关闭开关 |
| C2 | 彩带只框住被操作的那一个窗口，不框整个屏幕 |
| C3 | 风格必须与前台的观察框明显区分：前台是整屏的冷色霓虹，后台是暖色的虚线环 |
| C4 | 彩带左上角显示一行小标签，写明"后台操作中 · 软件名" |
| C5 | 彩带不得抢焦点、不得拦截点击、不得出现在截图里 |
| C6 | 最后一条动作结束后保留约 4 秒再消失；同一窗口连续操作时保持常亮，不闪烁 |
| C7 | 目标窗口被其他窗口完全遮住、或系统拿不到窗口坐标时，不画彩带，操作照常进行 |
| C8 | 彩带是提示，不是门禁：画不出来、画失败，都不得阻断动作 |

### D. 举手（临时置前）

| 编号 | 需求 |
|---|---|
| D1 | 举手只用于两种情况：目标窗口没有露出来，或某个控件明确要求窗口在前台 |
| D2 | 举手由后台 agent 自主决定，是一次显式动作，会话记录里可见 |
| D3 | 举手不设空闲门槛：用户正在使用也不阻止 |
| D4 | 举手只把目标软件置前，仍然用结构化信息操作，不移动鼠标、不模拟按键 |
| D5 | 举手是临时的：任务段结束、主动放下、或超时（90 秒）自动放下；放下时把前台还给原本在前的软件 |
| D6 | 举手失败（系统不允许置前）时，不得使用非常规手段强行置前；直接回传前台 |

### E. 不提问与回传

| 编号 | 需求 |
|---|---|
| E1 | **后台模式不包含"向用户提问"的能力**，该能力在后台模式中不存在 |
| E2 | 后台只在"做不到"时停下：没有权限、没有语义动作、软件无响应；"用户正在使用"不再算做不到 |
| E3 | 停下前必须先尝试替代路径：改用文件、命令、其他软件 |
| E4 | 回传内容必须包含：做了什么、卡在哪、为什么需要用户、可选方案、风险提示 |
| E5 | 回传后由前台向用户提问，并决定后续：前台自己完成，或再派一次 |
| E6 | 不可逆操作（发送消息、删除、支付、覆盖保存）不单独拦截，和普通动作一样执行 |

### F. 安装与平台

| 编号 | 需求 |
|---|---|
| F1 | 安装插件后两个模式都可用，不需要任何额外下载、安装或配置 |
| F2 | 全新 Windows 机器（未修改系统安全设置）与全新 macOS 机器上，用户流程一致 |
| F3 | 不出现命令行窗口，不要求用户设置路径或环境变量 |
| F4 | 卸载插件后不留下全局残留 |

### G. 数据与隐私

| 编号 | 需求 |
|---|---|
| G1 | 只读取完成当前任务所需的界面内容；不上传任何界面内容 |
| G2 | 界面内容可能含隐私，日志默认不记录具体内容 |
| G3 | 用户可关闭"后台桌面操作"开关；关闭后后台退回纯文件/命令模式 |

### H. 稳定性

| 编号 | 需求 |
|---|---|
| H1 | 单个界面动作一般在数秒内完成；长时间等待必须对用户可见 |
| H2 | 操作失败不得让任务卡死，必须有超时与明确的失败结论 |
| H3 | 系统不允许的操作不得反复重试刷屏 |

### I. 用户控制

| 编号 | 需求 |
|---|---|
| I1 | 用户能看见后台正在操作哪个窗口（彩带），以及在做什么（会话记录可读） |
| I2 | 用户能随时停止：一个动作停掉当前后台任务，正在进行的界面操作立即中止 |
| I3 | 所有界面操作留痕，可在会话里回看 |

## 8. 状态与规则

| 目标窗口位置 | 用户是否在操作 | 后台行为 |
|---|---|---|
| 前到最前 | 在用 | 直接操作，彩带标出这个窗口 |
| 前到最前 | 不在用 | 直接操作，彩带照常显示 |
| 在后台 | 任意 | 直接操作；彩带画出来但可能被其他窗口遮住 |
| 没有露出来 | 任意 | 无头操作；控件要求前台时才举手 |
| 同一软件已有另一个后台任务 | 任意 | 等待，不得并行操作同一个软件 |
| 前台模式正在物理输入 | 任意 | 等它结束再动同一个软件 |

## 9. 主流程

**流程一：全程后台**

```
前台派活 → 后台读写文件 → 后台在目标窗口里操作（窗口四周亮起暖色彩带）→ 完成后回传结论
```

用户屏幕的变化只有那条彩带。

**流程二：需要前台**

```
后台发现控件要求前台 → 举手 → 窗口置前 → 操作 → 放下并还原前台
```

**流程三：做不到**

```
后台尝试替代路径 → 都不行 → 停下 → 把结论与可选项回传前台 → 前台向用户提问
```

## 10. 用户可见文案（示例）

- 彩带标签：「后台操作中 · 微信」——只说软件名，不暴露界面内容。
- 后台开始处理：「后台正在处理：在 Word 里排版」——出现在会话记录里，不弹窗。
- 举手（窗口被叫到前面时）：「需要把 Excel 切到前面几秒」。
- 交回前台：「这一步做不了：微信没有可操作的无障碍接口。后台已停下，等你决定下一步。」
- 权限/能力不可用：「这台电脑的系统设置不允许后台操作其他软件」。

## 11. 验收标准

1. 用户正在 Word 里打字时，后台任务需要在 Word 里改一段文字 → 后台照常操作，Word 四周出现暖色彩带，用户原有的按键不丢。
2. 后台需要操作一个在后台的 Excel → 直接操作，彩带框住 Excel 窗口（可能被挡）。
3. 后台无头操作被拒绝 → 举手 → Excel 置前 → 用户同时点了一下鼠标 → 后台不中断，彩带继续显示。
4. 后台全程不出现任何提问卡片（该能力不存在）。
5. 最后一条动作结束约 4 秒后，彩带消失。
6. 后台尝试对"发送消息"类动作 → 和普通动作一样执行，不额外停下。
7. 全新 Windows 机器 + 全新 macOS 机器：装完插件即可完成一次"打开软件 → 输入文字 → 保存"的任务，无额外下载。
8. 断网状态下，两个模式都能使用。
9. 会话记录能看到后台操作过哪些软件、做了什么。
10. 关闭"后台桌面操作"开关后，后台无法碰界面，且任务不会因此卡死。
11. 系统拿不到窗口坐标时，动作照常完成，只是没有彩带。

## 12. 已经定下的取舍

1. **不提供"始终允许"设置。** 不可逆操作也不单独拦截，不再有"先问一句再发"的流程。
2. **彩带默认开启且不可关闭**，只在会话记录之外提供可视提示，不弹通知、不弹卡片。
3. **彩带由后台自己画**：琥珀 → 玫瑰色的虚线环，带缓慢流动与呼吸，左上角一行"后台操作中 · 软件名"。前台模式仍是对的整屏青紫霓虹，两者一眼可区分。
4. **没有"停止"按钮**：用户停任务通过会话里的停止动作完成，彩带本身只做提示、不接收点击。
5. **不再有"用户在用就停"这条规则**，也不再有"离开 60 秒才允许操作"；取代它的是可见性。

## 13. 术语

| 术语 | 含义 |
|---|---|
| 前台模式 | 现有的 Computer Use 模式，占用屏幕与鼠标 |
| 后台模式 | 新增模式：标准能力 + 桌面操作能力，默认不占屏幕 |
| 静默 | 不动鼠标、不抢焦点、不切换前台应用 |
| 彩带 | 后台操作某个窗口时，围在它四周的暖色虚线环与标签 |
| 举手 | 把某个软件临时置前，仍然用结构化信息操作 |
| 回传 | 后台把"做不到"的事项交回前台 |
